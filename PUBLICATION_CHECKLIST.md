# Public release checklist

This checklist records the technical preflight and maintainer responsibilities. It is not a legal clearance.

## Technical verification performed on 2026-10-11

- In an isolated Python 3.14.5 environment, `python -m unittest discover -s tests -v` passed all **15 tests** with Qt offscreen. Key tested packages were NumPy 2.5.4, pandas 3.0.6, SciPy 1.18.1, Matplotlib 3.11.2, Pillow 12.3.0, and PySide6-Essentials 6.12.0. The 2D pan/reset test was updated to account for the viewport changing size when its dock is laid out; no application behavior was changed for that test.
- The source-launcher `--self-test` passed: version 2.4.2, expected synthetic M² values, icon and schematic resources, 2D/3D rendering, and principle animation.
- The three checked-in CSVs are deterministically generated by `tools/generate_synthetic_examples.py`. The public configuration uses example device IDs. No old experimental samples, wheel files, executable, installer, or old manual were placed in this folder.
- These checks used synthetic data and an offscreen display. They are **not** a hardware validation, ISO certification, uncertainty analysis, or clean-machine installer test.

## Maintainer responsibilities for public distribution

- Confirm authorship and authority to apply MIT to every source file, document, and asset. Check employment, client, collaboration, and contract terms. Removing product names does not establish whether any code or interface expression was copied or is sufficiently independent.
- Preserve `LICENSE`, `LEGAL_NOTICE.md`, `THIRD_PARTY_NOTICES.md`, `third_party_licenses/`, and `assets/PROVENANCE.md`. MIT applies only to rights contributors can grant. Review the exact dependency licenses again for any future binary.
- Do not add the former user-supplied reference illustration, vendor manuals, extracted graphics, proprietary SDKs, or old installers without verified permission. Review branding and interface similarity for possible confusion; the independent name and disclaimer do not themselves grant third-party rights.
- Review every staged file and **the Git history intended for push** for private data, logs, identifiers, and binaries. Starting a fresh repository inside this folder avoids importing old private history; do not push the whole desktop development directory.
- For a binary release, audit exact bundled dependency versions and satisfy the applicable notices, license, corresponding-source and library-replacement requirements. Then verify the installer on an authorized clean Windows system. The build templates here are not a cleared binary distribution.
- Seek qualified legal advice in China if ownership, copying, trademarks, design, patents, or contract restrictions remain uncertain. Public release is the maintainer's decision.

Legal background: the [Chinese Software Protection Regulation](https://ipc.court.gov.cn/zh-cn/news/view-407.html) addresses software authorship, commissioned and employment-created work, and excludes abstract ideas and mathematical concepts from software-copyright protection. The [Chinese Trademark Law](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_3107cd5f8af445619ec74267aaebcc7f.html) addresses confusing use of marks. These links are context, not a legal opinion about this project.
